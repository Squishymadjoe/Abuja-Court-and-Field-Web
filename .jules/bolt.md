# Bolt's Performance Journal

## 2025-03-01 - Same Element Reference Optimization for Page Routing
**Learning:** In App.tsx, state variables (such as audio player state `currentEpisode` and `isPlaying`) are placed at the root application level. This means any update to the audio playback state triggers a complete re-render of the entire App tree. By default, this re-evaluates and re-renders the active page component (e.g. Home, Episodes, etc.) and all of its descendants, leading to substantial "render leaks" during simple actions like playing or pausing a track.
Rather than wrapping all individual page and child components in redundant `React.memo` wrappers, we can leverage React's "Same Element Reference" (SER) bail-out. By stabilizing handlers with `useCallback` and memoizing the switch-case routing return value with `useMemo` with only `currentPage` and stable callbacks in the dependency array, React automatically bails out of re-rendering the active page component on unrelated root state updates. This achieves a 100% reduction in unnecessary page component re-renders (from 6 down to 0 during player toggle interactions).
**Action:** Always identify root-level state updates that are decoupled from main content components. Use `useCallback` for event handlers and `useMemo` for manual routing switch-case elements to prevent render leaks across page transitions.
